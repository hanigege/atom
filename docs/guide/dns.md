# DNS 和域名学习

一句话：**atom 的 DNS 决定每个域名走直连还是走代理**。国内的域名返回真实 IP，客户端直接连；国外的域名返回 FakeIP（默认 `28.x.x.x`），连接到了 atom 再交给代理内核。

下面讲一次查询怎么被判断，以及面板「DNS」页里各项设置的意思。

## 一次查询怎么走

客户端问 `www.example.com` 的地址时，atom 按下面的顺序判断，**第一步有结论就不再往下走**：

| 顺序 | 看什么 | 结果 |
|---|---|---|
| 1 | 重写、hosts、类型屏蔽 | 按设置直接应答 |
| 2 | [规则表](rules.md) | 第一条命中的规则说了算：直连、代理到某个组，或屏蔽 |
| 3 | 记忆无 V4、记忆无 V6 | 已经确认没有 IPv4（或 IPv6）的域名，对应的查询直接返回空 |
| 4 | 缓存 | 最近查过的，直接用缓存里的应答 |
| 5 | geosite 名单 | 在国外域名名单（geosite 非中国）里：代理；在中国域名名单（geosite-cn）里：直连 |
| 6 | 域名学习的记忆 | 记忆代理：代理；记忆直连：直连 |
| 7 | 探测 | 都没有的新域名，先向上游问一次真实地址，看 IP 在哪 |

第 7 步的探测：

- 应答里有国内 IP（geoip-cn，或「直连 IP」表里的地址）→ **直连**，把真实 IP 返回给客户端，并把这个域名记进「记忆直连」；
- 应答里只有国外 IP → **代理**，改为返回 FakeIP，并把域名记进「记忆代理」。

所以一个新域名第一次被查时会多花一次上游查询，之后在有效期内直接按记忆走。

「直连」的意思是返回真实 IP；「代理」的意思是返回 FakeIP，没有规则指定组的走兜底分组。规则、名单或记忆判定走代理的域名，A 查询拿到 IPv4 的 FakeIP，AAAA 查询返回空，都不发给任何 DNS，由节点在远端解析。

### 兼容模式和安全模式

「DNS → 高级设置」的「核心运行模式」决定向谁要真实 IP：

- **兼容模式**（默认）：第 7 步的探测和记忆直连的域名都问国内 DNS，速度快。新域名探测时会问一次国内 DNS，即使最后判定走代理；
- **安全模式**：第 7 步的探测和记忆直连的域名都只问「国外（带 ECS）」组，国外没结果也不回退到国内，更不容易被污染或泄露查询。

## 域名学习

域名学习就是把第 7 步探测的结论，以及刷新时发现的几种特殊情况，记下来给之后的查询用。一共五类：

| 类别 | 是什么 | 怎么学到 | 有效期 |
|---|---|---|---|
| 记忆直连 | 解析出国内 IP 的域名 | 探测时应答里有国内 IP | 7 天 |
| 记忆代理 | 只解析出国外 IP 的域名 | 探测时应答里只有国外 IP | 7 天 |
| 记忆无 V6 | 没有公网 IPv6 地址的域名 | AAAA 查询正常应答，但里面没有公网 IPv6（`2000::/3`），比如只有内网地址 | 1 天 |
| 记忆无 V4 | 国内国外都查不到 IPv4 的域名 | 只在刷新时学到（见下文） | 8 天 |
| 特殊域名 | 国内 DNS 查不到 IPv4、国外 DNS 查得到的域名 | 只在刷新时学到 | 8 天 |

补充几点：

- 已经在 geosite 名单里的域名不会记进记忆直连、记忆代理，因为名单总是先于记忆（上表第 5 步在第 6 步前面），记了也用不上；
- 上游出错（比如 SERVFAIL）不算「没有 IPv4/IPv6」，不会被记下来；
- 记忆无 V4、记忆无 V6 生效的前提是「空结果屏蔽」开着（默认开）；
- 特殊域名多是不在国内提供服务的网站。这一类只是记录，不改变之后的普通查询；想让它一直走代理，给它写一条规则。

「DNS → 高级设置 → 域名学习」里列出前四类（面板上叫直连、代理、无 V4、无 V6），可以看条数，编辑上限和有效期，单独关掉或清空某一类。特殊域名不在面板上显示。

### 上限

每类默认最多 20000 条。满了以后先删掉已过期的，还不够就删掉最久没被确认的那一部分。

### 有效期

**有效期从「最后一次被确认」开始算**。同一条学习规则再次命中这个域名，就算确认一次，重新计时；超过有效期没被确认，记录才会删除。

要注意：**按记忆走不算确认**。记忆直连、记忆代理的域名在有效期内直接按记忆分流，不会再去探测，所以它们在学到 7 天后到期。到期后，下一次没命中缓存的查询（或下一次定期刷新）会重新探测，再学一次。这样：

- **情况没变的域名会被重新学回同一类。** 比如 `a.com` 解析出国内 IP，学成记忆直连；7 天后记录到期，再探测时还是国内 IP，又记成记忆直连，客户端感觉不到变化。
- **情况变了的域名在重新探测时改正。** 比如 `a.com` 换成了国外 CDN：在原记录到期前它仍按记忆直连走；到期后下一次重新探测，应答里只剩国外 IP，就学进记忆代理。

等不及的话，可以在「域名学习」里清空记忆直连，或者在规则表里给它写一条规则（规则总是优先于学习）。

记忆无 V6 的有效期只有 1 天，到期后下一次 AAAA 查询会重新学到。记忆无 V4 和特殊域名靠定期刷新来确认，见下一节。

## 定期刷新

定期刷新默认开着，**每 7 天**做一次：

1. 清空 DNS 缓存（不清学习记录）；
2. 把「域名全集」里最近 30 天有客户端查过的域名，按每秒 10 个的速度重新解析一遍；
3. 结果写回缓存和学习记录。

「域名全集」记录了客户端查过的每个域名和最后一次查询的日期，记录本身不会过期。刷新自己的查询不算「客户端查过」，所以 30 天没人用的域名不再参与刷新。

刷新和平时的查询有两点不同：

- 平时第一次问没有 IPv4 就到此为止；**刷新时会再问一次国外 DNS**。安全模式下，名单外的域名和记忆直连的域名第一次问的是「国外（带 ECS）」，第二次问不带 ECS 的国外组；中国域名名单（geosite-cn）里的域名不管哪种模式，都先问国内 DNS。「记忆无 V4」（两次都没有 IPv4）和「特殊域名」（国内没有、国外有）都要比较两次的结果，所以只在刷新时学到；
- 刷新时，名单里判定直连的域名如果国内没有 IPv4、国外有国外 IPv4，这一次刷新查询会改为返回 FakeIP，同时记成特殊域名；
- 平时记忆无 V4/V6 的域名直接返回空；刷新时会重新查一遍，用来确认它们。

刷新时重新解析命中学习规则，也算一次确认。所以开着定期刷新时，记忆无 V4 和特殊域名基本只会因为情况变了才过期。它们的有效期是 **8 天 = 刷新间隔 7 天 + 1 天余量**，保证下一次刷新前不会过期。

> 在面板里改刷新间隔或这两类的有效期时，有效期要比刷新间隔长，否则记录会在两次刷新之间过期。

「DNS → 高级设置 → 域名学习」下面可以改刷新间隔（分钟）、关掉定期刷新，或者点「立即刷新」。切换核心运行模式后也会自动刷新一次。

## 缓存

查过的应答会先存在缓存里，再有人问同一个域名就不用再问上游。

| 缓存 | 存什么 |
|---|---|
| 全局缓存（兼容模式、安全模式各一份） | 没命中规则的查询最先查这里，只存真实 IP 的应答，不存 FakeIP。两种模式分开存，切换时互不影响 |
| 国内查询缓存 | 国内 DNS 的应答 |
| 国外查询缓存、国外查询缓存·带 ECS | 国外 DNS 的应答 |
| 规则缓存 | 直连规则指定了上游组时，每个组一份 |

- **过期保留**（默认 7 天）：应答的 TTL 到了以后，在这段时间内仍可使用，减少等待；
- **写盘间隔**（默认 6 小时）：缓存定期写到磁盘，重启后还在；
- 保存规则会清空两份全局缓存；定期刷新会清空 DNS 缓存；切换核心运行模式会清空全局缓存并刷新一次。「DNS → 高级设置 → 缓存」里也可以单独清空某一个。

## 上游组

上游就是 atom 去问的 DNS 服务器，分组管理，在「DNS → 上游」里编辑：

- **国内组**（默认阿里 DNS 的 UDP 和 DoH）：直连的域名、兼容模式下的探测、重写目标都问它；
- **国外组**（默认 Google 和 Cloudflare 的 DoH）：刷新时的二次确认，以及代理规则命中的非 A/AAAA 查询（比如 MX、TXT）问它；
- **国外（带 ECS）组**：安全模式下的探测和记忆直连问它，查询带上「ECS 地址」，让国外 DNS 按你所在的地区给 IP；
- **自建的组**：给直连规则指定上游用，比如让内网域名去问家里的路由器（见 [规则 · 动作](rules.md#动作)）。

一个组里有几个上游时，会同时发给其中几个，用最先成功的那个应答：默认的国内组、国外组同时问两个；在面板里保存过的组，同时问所有启用的上游（最多 20 个）。判定走代理的 A/AAAA 查询不问任何上游：A 查询的 FakeIP 由代理内核直接给出，AAAA 返回空。

## 统计和日志

- 「DNS → 日志」是查询日志，在「DNS → 高级设置 → 查询日志」里设置是否记录和最多保留多少条；
- 「DNS → 概览」的查询统计和各种排行**都是从查询日志算出来的**：清空查询日志，它们会一起清零；日志满了以后最旧的记录被挤掉，统计也只覆盖日志里还在的那部分；
- 面板上的「重置统计」会清空查询日志，并把缓存和上游的计数归零。
