# 安装和接入

## 准备一台机器

| 项目 | 要求 |
|---|---|
| 系统 | Debian 12+、Ubuntu 22.04+（systemd），或 Alpine 3.19+（OpenRC） |
| 架构 | x86_64 或 aarch64 |
| 形态 | 物理机或虚拟机。不支持 Docker、LXC 容器 |
| 网卡 | 单网卡旁路由要一张网卡，双网卡网关要两张（LAN 和 WAN） |
| 权限 | root |

53 端口不能被别的程序占用。向导会列出占用 53 端口的程序（比如 systemd-resolved），可以一键停用。

## 运行安装命令

```bash
curl -fsSL https://github.com/jasonxtt/atom/releases/latest/download/install.sh | sudo bash
```

Alpine 上先装 bash 和 curl，安装命令里不用 sudo：

```bash
apk add bash curl && curl -fsSL https://github.com/jasonxtt/atom/releases/latest/download/install.sh | bash
```

脚本按架构和系统选择安装包，下载后校验 sha256。GitHub 慢或者连不上时，会依次换用几个加速地址。准备好后，终端里会打印向导的网址和 6 位安装码：

```text
atom 安装器已就绪，请在浏览器打开：
  http://10.0.0.77:9996/

  =======================================
    安装码  012345
    请在浏览器输入此码。仅本次启动有效。
  =======================================
```

向导只接受来自局域网和本机的访问。启动 30 分钟后不再接受新的安装。

## 网页向导

| 步骤 | 内容 |
|---|---|
| 环境检查 | 检查系统和 53 端口。端口被占用时，可以在这里停用占用它的程序 |
| 网络 | 选择拓扑和网卡，设置面板端口（默认 80），可选设置面板的用户名和密码（留空就不需要登录） |
| DNS 上游 | 国内和国外上游，默认值一般不用改 |
| 代理内核 | 选择 sing-box 或 mihomo，没有默认值。以后可以在面板里切换，区别见 [节点、节点组和订阅](proxy.md#两种内核) |
| 代理 | FakeIP 网段、mixed 端口，还可以导入节点（选 mihomo 时也可以填订阅地址）。导入的节点会放进「默认代理」组 |
| 确认 | 检查各项设置，然后开始安装。装完会自检，并自动跳转到面板 |

没有导入节点也能装完，但这时所有判定为走代理的流量都会被拒绝。装完后到面板的「节点」页导入即可。

## 选择拓扑

### 单网卡旁路由

atom 和主路由在同一网段，客户端的默认网关仍然是主路由：

```text
客户端 ──默认网关──> 主路由 ──静态路由：FakeIP 网段、要代理的网段──> atom
   ^                                                              │
   └──────────────────── atom 直接回包（同一网段）──────────────────┘
```

这时主路由只看到连接去程的包。主路由的防火墙里如果有「丢弃 invalid 状态」的规则（比如 RouterOS 的默认防火墙），可能会丢掉这些连接的后续包。处理办法任选一种：

- 在向导里勾选「回包经主路由」，回包改为经主路由发回，主路由能看到连接的两个方向；
- 在主路由的转发链里，目标是 FakeIP 网段和代理网段的包，在 drop invalid 之前放行；
- 用 DHCP option 121 把这些网段的路由直接下发给客户端，客户端就绕过主路由，直接发给 atom。

### 双网卡网关

atom 的 LAN 口接主路由（比如主路由的 WAN2），WAN 口接上级网络：

```text
客户端 ──> 主路由 ──FakeIP 网段、要代理的网段──> atom 的 LAN 口 ─┬─ TCP、UDP → 代理内核 → 节点或直连
                                                               └─ 其他（比如 ping）→ NAT → WAN 口
```

客户端不在 LAN 口所在的网段时（比如经过 LAN 侧另一台路由器过来），要在向导里填「LAN 侧网关」和「客户端网段」，否则本机的回包会从 WAN 口发出去。向导会按本机现有的路由预填这两项。

双网卡网关会阻止从 WAN 侧访问本机的面板、DNS 和代理端口。

## 在主路由上设置

两种拓扑都要做：

1. **静态路由**：把 FakeIP 网段（默认 `28.0.0.0/8`）指向 atom 的 LAN IP。规则里写了目标 IP 网段（比如 Telegram 的 IP），也把这些网段指过来。双网卡网关就是让这些网段走接 atom 的那个口。
2. **客户端 DNS**：把 DHCP 下发的 DNS 改成 atom 的 LAN IP。

转发到 atom 的 TCP、UDP 流量全部交给代理内核：FakeIP 按 DNS 给的绑定出站；真实 IP 按规则里的 IP、端口条件出站；都没命中的走兜底分组。所以**不想走代理的网段不要转给 atom**。

只想让个别设备使用代理时，可以不改路由，直接在设备上把代理设为 atom 的 mixed 端口（默认 `7890`，同时支持 HTTP 和 SOCKS5）。

## 检查是否生效

在客户端上：

```bash
nslookup www.google.com      # 应该返回 28.x.x.x 这样的 FakeIP
nslookup www.baidu.com       # 应该返回真实 IP
```

然后打开面板的「连接」页，访问一个走代理的网站，应该能看到这条连接和它走的节点。也可以在「规则」页顶部输入域名，测试它会命中哪条规则。
