# 规则

## 一个域名怎么被判断

| 顺序 | 环节 | 内容 |
|---|---|---|
| 1 | 系统固定项 | 重写、hosts、本地 PTR、类型屏蔽，不能调整 |
| 2 | 规则表 | 在「规则」页编辑，从上往下匹配，第一条命中的规则生效 |
| 3 | 国内外判断 | 规则表都没命中时，按 geosite、geoip 和域名学习判断：国外返回 FakeIP，走兜底分组；国内返回真实 IP，直连 |

大部分域名靠第 3 步就能分对，规则表只需要写例外情况：哪些域名走指定的节点组、哪些要屏蔽、哪些设备不走代理。第 3 步的细节（域名学习、定期刷新、缓存）见 [DNS 和域名学习](dns.md)。

## 动作

| 动作 | DNS 返回 | 流量 |
|---|---|---|
| 代理 → 某个组 | FakeIP，不查询国内 DNS | 走这个组 |
| 直连 | 国内 DNS 的结果，也可以指定一个上游组 | 不经过代理 |
| 屏蔽 | 空应答 | — |

「代理」可以选任意节点组，也可以选兜底分组。直连规则还有两个选项：指定 DNS 上游组（比如让内网域名去问家里的路由器），以及「不缓存」（适合 IP 经常变的 DDNS 域名）。

## 条件

规则编辑页的条件分三类：

- **内置规则集**：从 MetaCubeX、blackmatrix7 的规则目录里挑选，比如 `netflix`、`openai`、`telegram`；
- **自定义规则集**：自己添加的远程列表地址或本地列表，在「规则 → 规则集」里管理；
- **自定义条件**：域名（完整、后缀、关键字、正则）、目标 IP 网段（支持单个 IP、CIDR 和起止 IP 范围，如 `10.0.0.10-10.0.0.20`）、目标端口、网络（TCP/UDP）、客户端（同样支持单个 IP、CIDR 和起止 IP 范围）。

条件之间的关系：

- 域名类条件（各种域名写法和规则集）之间是「或」；
- 客户端条件和域名类条件之间是「且」；
- IP 网段和域名条件分别生效：域名由 DNS 匹配，IP 网段由代理内核匹配，动作相同；
- 端口、网络、IP 网段之间是「且」。

编辑页会在条件块之间标出「或」「且」。

### 客户端条件

- **同时带客户端和域名条件**时，动作只能是直连或屏蔽（代理核心按域名记录出口，不能按「客户端 + 域名」独立绑定代理组）。
- **只有客户端条件**（不带域名、IP、端口、网络）时，除了直连和屏蔽，还可以选择**代理**（可选任意节点组或兜底分组），实现指定设备的全覆盖代理（连 AI/Google 等域名分流规则一并覆写，不影响其他设备）。

常见写法：

- 某些设备不走代理：「名单内的客户端」填这些设备 → 直连（也可选指定 DNS 上游组）；
- 只有某些设备走代理：「名单外的客户端」填这些设备 → 直连；
- 某些设备全局走代理：「名单内的客户端」填这些设备 → 代理（选指定节点组或兜底分组）。

顺序要求：

- 客户端直连规则通常放在最前面；放在某条代理规则后面的话，这些设备查询那条规则里的域名时，仍然会先命中代理。
- **客户端代理规则必须排在所有域名代理规则之上**（上方仍可放局域网域名直连、广告屏蔽等直连/屏蔽规则）。新建保存时会自动插到第一条域名代理规则之前；不能拖到域名代理规则下方。
- 客户端规则面向透明代理（旁路 FakeIP）；经 7890 mixed 代理端口发起的请求由代理内核本机回查 DNS，AtomDNS 看不到客户端 IP。

### IP、端口和网络条件

这些条件由代理内核匹配，只对**真实 IP** 的连接生效。用于 Telegram 这类直接连 IP 的应用，或者「某个网段的 UDP 443 端口直连」这类场景。

- DNS 查询时不知道端口，所以带端口或网络条件的规则不能同时带域名或客户端条件；
- IP 网段不能和 FakeIP 网段重叠；
- 流量要先到达 atom 才会被匹配：单网卡旁路由下，要在主路由上把这些网段也路由到 atom（见 [安装和接入](install.md#在主路由上设置)）。

拿到 FakeIP 的连接一律按 DNS 给的绑定或兜底分组出站，不再经过 IP、端口和网络规则。

## 默认规则表

新安装时规则表里有两条规则：

1. **代理修正**：geosite-cn 里实际在国外的域名 → 代理到兜底分组；
2. **直连修正**：geolocation-!cn 里实际在国内的域名 → 直连。

默认不屏蔽广告。要屏蔽的话，新建一条规则，条件选规则集「广告（AdGuard 规则）」或目录里的广告规则集，动作选屏蔽。某个域名被误杀时，写一条直连规则拖到屏蔽规则上面即可。

## 规则集的更新

内置规则集和远程规则集每天自动更新，也可以在「规则 → 规则集」里手动刷新。`geosite_cn`、`geosite_no_cn`、`geoip_cn` 是国内外判断要用的，不能删除，但可以改下载地址。

## 改动后多久生效

规则保存后立刻生效，DNS 不中断。atom 会：

1. 清空 DNS 缓存；
2. 用新规则重新计算最近查询过的域名，把有变化的绑定直接推给代理内核。客户端手里已有的 FakeIP，之后的连接会按新规则走。

例外是在**直连和代理之间切换**的域名：客户端缓存的是真实 IP，只能等它的 DNS 缓存过期。直连应答的 TTL 最长 300 秒（可以在「DNS → 设置」的 TTL 上限里修改），所以最多等 5 分钟。急的话可以在客户端上清一下 DNS 缓存。

## 测试一个域名

「规则」页顶部可以输入域名（以及可选的客户端 IP），会显示它命中哪条规则，或者落到国内外判断后的结果。改规则前后都可以用它确认。
