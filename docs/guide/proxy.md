# 节点、节点组和订阅

## 节点

在「节点 → 添加节点」里粘贴，支持三种格式：

| 格式 | 说明 |
|---|---|
| 分享链接 | 每行一个：`vless://`、`vmess://`、`trojan://`、`ss://`、`hysteria2://`（`hy2://`）、`tuic://`、`anytls://`、`socks://` |
| Clash / mihomo YAML | 整份配置、`proxies` 列表或单个节点都可以。还支持 snell、ssh、hysteria、wireguard |
| sing-box JSON | 单个 outbound、数组或整份配置（只取代理类型的 outbound） |

批量导入要么全部成功，要么全部不导入：只要有一项转换失败，就整批拒绝，错误信息会指出是第几项。

为了安全，面板不会回显节点的密码、UUID、私钥这类凭据。修改节点名称不影响连接；要改连接参数，需要重新粘贴整个节点。

### 前置代理（链式代理）

手动节点可以指定「前置代理」，让该节点通过另一个手动节点或非兜底节点组中转连接（sing-box 生成 `detour`，mihomo 生成 `dialer-proxy`）。添加单个节点、批量导入节点或编辑节点时均可设置；不能形成循环引用。规则页的 dry-run 会展开并显示完整的链式路径。

## 节点组

| 类型 | 行为 | 内核 |
|---|---|---|
| 手动（selector） | 手动选择用哪个成员 | 两种都支持 |
| 自动测速（urltest） | 定时测速，自动选延迟最低的成员 | 两种都支持 |
| 故障转移（fallback） | 按顺序选第一个可用的成员 | 仅 mihomo |
| 负载均衡（load-balance） | 按策略把连接分到多个成员上 | 仅 mihomo |

- 组的成员可以是节点，也可以是其他组（不能循环引用）。
- **名称筛选**：给组设一个关键字或正则，比如 `香港` 或 `^(HK|香港)`。名称匹配的节点会自动加入，之后新增的节点也一样，不用逐个添加。
- **默认代理**是内置组，不能删除。新安装时导入的节点都在这个组里。
- **快捷创建**：点「+ 添加节点组」可按地区（内置正则筛选）或按服务（自动联动内置目录规则集）快速建组；规则页也支持按服务批量创建规则。
- 删除一个被规则引用的组时，面板会列出这些规则。确认删除后，这些规则改为代理到兜底分组。

### 兜底分组

兜底分组是一个手动组，成员默认是所有节点组，新建的组会自动加入。以下流量都走它：

- 规则表没命中、国内外判断为国外的域名；
- 规则里写了「代理 → 兜底分组」的域名；
- 转发到 atom、但没有命中任何 IP 规则的真实 IP 连接。

兜底分组不能设为直连。默认选中「默认代理」。

## 订阅（仅 mihomo）

在「节点 → 订阅」里添加机场的订阅地址。订阅由 mihomo 自己下载、缓存和做健康检查，atom 不转换订阅内容。可以设置：

- 更新间隔；
- 节点名称筛选（正则）；
- 下载时经过哪个手动节点（默认直连，适合订阅地址本身被墙的情况）；
- 下载时用的 User-Agent（有的机场按 UA 返回不同格式）。

节点组在「订阅」里选择从哪些订阅取节点，或者选「全部订阅」，以后新加的订阅也会自动包含。组的名称筛选同时作用于手动节点和订阅节点。

保存订阅时，atom 会确认 mihomo 已经加载出节点。下载失败、格式不兼容或筛选后一个节点都没有时，保存会被撤销。

## 两种内核

在「设置 → 代理」的「代理内核」里切换。节点、节点组、规则和端口两边共用。

| | sing-box | mihomo |
|---|---|---|
| 订阅 | 不支持 | 支持 |
| fallback、load-balance 组 | 不支持 | 支持 |
| naive、独立的 shadowtls 节点 | 支持 | 不支持 |

切换前，面板会列出受影响的内容，确认后才执行：

- **mihomo → sing-box**：订阅节点暂时不可用，订阅设置保留，切回 mihomo 后恢复。每个 fallback、load-balance 组都要选择处理方式：转换为自动测速（永久修改），或删除。
- **sing-box → mihomo**：列出 mihomo 不支持的节点及原因。这些节点保留但不生效，切回 sing-box 后恢复。

切换时，atom 先校验新配置、启动新内核，确认它就绪后才停掉旧内核，失败会恢复原来的内核。切换后现有的代理连接会断开一次，客户端缓存的 FakeIP 需要重新查询。

## 切换节点时自动断开连接

在「设置 → 代理」中可开关「切换节点时自动断开连接」（**默认关闭**，新安装及从旧版本升级均保持关闭）：

- 关闭时：切换手动节点组或兜底分组只影响新建立的连接，已有连接继续保持；
- 开启时：切换节点后自动关闭原节点上的既有连接（含经由该组的链式代理连接），不影响切换后新建立的连接。若同时存在大量旧连接且限时内未全部断开，面板会给出告警提示。

## 不经过透明代理使用

atom 的 mixed 端口（默认 `7890`，HTTP 和 SOCKS5 共用）也按同一套规则分流，可以在单台设备或某个程序里直接设为代理。
